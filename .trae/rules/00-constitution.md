1. 核心原则
   - 允许破坏性变更，无需向后兼容
   - 修改公共 API 后同步修改所有调用方
   - 一个逻辑单元（功能/修复/重构）的所有文件修改完成后，统一运行 `pnpm run ci`，未通过则继续修复
   - 优先使用现有技术栈解决问题，禁止重复引入同类库

2. 技术栈基线
   - Electron ^42
   - React ^19
   - TypeScript ^6
   - Zustand ^5
   - Tailwind CSS ^4
   - i18next ^26

3. 加新库
   - 现有库能搞定的，禁止引入同类库
   - 优先用项目里已存在的库
   - 如果确定新的库更好用，可以替换现有库

4. 改公共 API
   - 改函数签名、组件 Props、Store 接口时，全局搜索并同步修改所有调用方
   - 禁止只改定义留下编译错误
   - 允许直接删除旧代码，不保留兼容层

5. 目录与模块
   - 新功能优先放到最贴近的已有目录
   - 禁止在 main 与 renderer 之间直接引用对方模块

6. 规则优先级
   - `rules/` 编号小的优先（00 > 01）
   - 规则与现有代码冲突时，以规则为准

7. 规则进化
   - 规则是活的文档，不是死的教条
   - 当规则与已安装的 npm 包的实际用法冲突时，以 npm 包为准，同步更新规则文件
   - 当规则与最新主流标准冲突时，以最新标准为准，同步更新规则文件
   - 修改规则后运行 `pnpm run ci` 验证，未通过则回滚规则修改
