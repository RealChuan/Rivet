1. 铁律
   - 以一个逻辑单元（一个功能、一个修复、一次重构）为单位，该单元涉及的所有文件修改完成后，统一运行 `npm run ci`
   - `npm run ci` 未通过时，禁止标记该任务完成，必须继续修复直至通过
   - `npm run ci` 是最终门禁，优先级高于一切其他规则

2. 什么是"逻辑单元"
   - 修复一个 bug：修改了组件 A、Store B、类型 C，这三个文件是一个单元
   - 新增一个功能：修改了 IPC handler、Preload、组件、i18n key，这些文件是一个单元
   - 重构一个模块：重命名了文件并同步改了所有 import，这些改动是一个单元
   - 允许在一个单元内批量修改多个文件，不要求每改一个文件就 CI

3. CI 通过标准
   - `npm run lint` 零错误
   - `npm run test` 零失败
   - `npm run build` 零报错
   - TypeScript 编译零类型错误

4. 修改流程
   1. 分析需求，确定涉及的文件范围
   2. 批量修改该逻辑单元内的所有文件（允许破坏性变更，无需兼容旧代码）
   3. 同步修改所有调用方和关联测试
   4. 运行 `npm run ci`
   5. 未通过 → 在该单元内继续修复，不要开新任务
   6. 通过 → 标记该逻辑单元完成

5. 禁止行为
   - 禁止在 CI 未通过时声称"已完成"或"先这样后面再修"
   - 禁止通过注释掉测试、跳过 lint 规则、改 CI 配置来让 CI 通过
   - 禁止只改定义留下多处编译错误未处理就结束任务
