# 文件浏览器移动/复制操作设计文档（SFTP / WebDAV）

> **适用范围**：基于 SFTP 或 WebDAV 协议的文件浏览器
> **目标**：实现稳定、可预测、用户友好的移动/复制功能，处理源为文件/文件夹/混合场景

---

## 1. 概述

本设计文档基于 Rivet 项目的实际代码实现，定义了从源路径列表到目标目录的移动（Move）和复制（Copy）操作的完整流程。

当前实现采用 **UI层 + 协议层** 的分层架构：

- **UI层**：处理用户交互、冲突检测、策略选择
- **协议层**：执行实际的远程文件操作

---

## 2. 术语定义

| 术语                      | 含义                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| **源路径（Source）**      | 单个文件或文件夹的远程绝对路径（`FileInfo.absolutePath`）         |
| **源列表（Sources）**     | 多个 `FileInfo` 对象组成的数组                                    |
| **目标目录（TargetDir）** | 用户选中的目标文件夹（`FileInfo` 对象）                           |
| **操作类型**              | `move` 或 `copy`                                                  |
| **路径规范化**            | 使用 `normalizePath()` 转换为绝对路径，统一使用 `/` 分隔符        |
| **自包含限制**            | 禁止目标目录等于源文件夹自身或为源的后代路径                      |

## 3. 前置限制规则（客户端校验）

所有限制在**发起任何网络请求前**执行校验。

### 3.1 通用规则（适用于移动 & 复制）

| 规则                     | 校验逻辑                                | 错误提示                     |
| ------------------------ | --------------------------------------- | ---------------------------- |
| **自包含检查**           | 使用 `isSubPath()` 判断目标是否为源的子路径 | “无法将文件夹移动/复制到自身或其子文件夹” |

### 3.2 自包含限制实现

在 `handleSelectTargetFolder` 中对每个源文件夹检查：

```typescript
for (const pendingFile of pendingFiles) {
  if (
    pendingFile.type === 'directory' &&
    isSubPath(pendingFile.absolutePath, targetDir.absolutePath)
  ) {
    throw new Error(t('toast.cannotMoveToSelf'))
  }
}
```

## 4. 同名冲突处理

### 4.1 冲突检测

在 `handleSelectTargetFolder` 中实现：

1. 调用 `protocol.list()` 获取目标目录下的所有文件
2. 使用 `Map<string, FileInfo>` 存储现有文件
3. 遍历待操作文件，检查是否存在同名项

### 4.2 冲突策略（用户可选项）

| 策略名称       | 行为                                                               | 适用场景           |
| -------------- | ------------------------------------------------------------------ | ------------------ |
| **覆盖（overwrite）** | 用源项目替换目标中的同名项目 | 用户明确知道要替换（仅复制操作可用） |
| **跳过（skip）**       | 不对该源项目执行任何操作，继续处理下一个                           | 保留目标现有内容   |
| **保留两者（keepBoth）** | 自动为目标中的源项目生成新名称                                   | 同时保留两份       |

> **注意**：移动操作默认不支持覆盖策略，默认使用 `keepBoth`

### 4.3 保留两者的重命名算法

在 `generateUniqueName()` 中实现：

```typescript
// 原始名：name.ext
// 新名称：name_YYYYMMDD_HHMMSS.ext
const now = new Date()
const timestamp = `${now.getFullYear()}${String(now.getMonth() + 1).padStart(2, '0')}${String(now.getDate()).padStart(2, '0')}_${String(now.getHours()).padStart(2, '0')}${String(now.getMinutes()).padStart(2, '0')}${String(now.getSeconds()).padStart(2, '0')}`
let newName = `${name}_${timestamp}${ext}`

// 若冲突，追加数字后缀 _1, _2... 最多尝试10次
for (let i = 1; i <= 10; i++) {
  newName = `${name}_${timestamp}_${i}${ext}`
  if (!existingNames.has(newName)) {
    return newName
  }
}
```

### 4.4 特殊冲突：类型不匹配

在 `canOverwrite()` 中判断：

```typescript
const canOverwrite = (conflict: ConflictItem) => {
  return conflict.sourceFile.type === conflict.targetFile?.type
}
```

- 类型不匹配时，禁用“覆盖”选项
- 显示提示：无法将文件覆盖到同名文件夹（或反之）

### 4.5 批量冲突 UI

冲突对话框支持：

- 逐项选择处理策略
- `应用到所有剩余冲突` 复选框
- 全局策略按钮：全部跳过、全部保留两者（复制操作还支持全部覆盖）

## 5. 操作执行流程

### 5.1 总流程图

```
开始
  │
  ▼
用户选择文件 → 点击复制/移动
  │
  ▼
打开目标文件夹对话框
  │
  ▼
用户选择目标文件夹
  │
  ▼
自包含检查 ──失败→ 提示错误，结束
  │ 成功
  ▼
获取目标目录文件列表（protocol.list）
  │
  ▼
冲突检测
  │
  ├─ 有冲突 ─→ 弹出冲突对话框 → 用户选择策略
  │                    │
  └─ 无冲突 ───────────┘
                       │
                       ▼
              执行操作（循环处理每个源）
                       │
                       ├─ 根据策略构造目标路径
                       ├─ 调用协议 API（MOVE/COPY）
                       └─ 任何错误 → 停止并报告
                       │
                       ▼
                    刷新目录，结束
```

### 5.2 核心实现逻辑

在 `executeOperation()` 中实现：

```typescript
for (const file of files) {
  const defaultTargetPath = getTargetPath(file.name, targetDir.absolutePath)
  const resolution = resolutionsMap.get(file.absolutePath)

  let targetPath = defaultTargetPath
  let shouldProcess = true

  if (resolution) {
    if (resolution.strategy === 'skip') {
      shouldProcess = false
    } else if (resolution.strategy === 'keepBoth') {
      const uniqueName = generateUniqueName(file.name, existingNamesSet)
      targetPath = getTargetPath(uniqueName, targetDir.absolutePath)
      existingNamesSet.add(uniqueName)
    }
  } else if (existingNamesSet.has(file.name)) {
    // 无冲突解决方案但存在同名文件，自动生成唯一名称
    const uniqueName = generateUniqueName(file.name, existingNamesSet)
    targetPath = getTargetPath(uniqueName, targetDir.absolutePath)
    existingNamesSet.add(uniqueName)
  }

  if (!shouldProcess) continue
  itemsToProcess.push({ file, targetPath })
}
```

### 5.3 移动操作

- 使用协议原生的 MOVE 命令（WebDAV：`moveFile`）
- 跨文件系统移动由底层协议处理，错误时直接提示用户

### 5.4 复制操作

- WebDAV：使用 `copyFile`（服务器端复制，高效）
- SFTP：客户端实现（读取 → 写入）

## 6. 协议适配注意事项

### 6.1 路径规范化函数

```typescript
export const normalizePath = (path: string): string => {
  const parts = path.split('/').filter(Boolean)
  if (parts.length === 0) return '/'
  return '/' + parts.join('/')
}
```

### 6.2 子路径判断

```typescript
export const isSubPath = (parent: string, child: string): boolean => {
  const normalizedParent = normalizePath(parent)
  const normalizedChild = normalizePath(child)
  if (normalizedParent === normalizedChild) return true
  return normalizedChild.startsWith(normalizedParent + '/')
}
```

### 6.3 优化策略

```
1. list(TargetDir) → Map<basename, FileInfo>
2. 对每个源，检查 map 中是否有同名项
   - 有 → 触发冲突处理
   - 无 → 直接执行
3. 自包含检查需要源文件夹信息，无法避免
```

## 7. 代码接口定义

### 7.1 核心类型定义

```typescript
interface FileInfo {
  name: string
  type: 'file' | 'directory'
  size: number
  modifyTime: number
  absolutePath: string
}

type ConflictStrategy = 'overwrite' | 'skip' | 'keepBoth'

interface ConflictItem {
  sourceFile: FileInfo
  targetFile: FileInfo | null
  targetExists: boolean
}

interface ConflictResolution {
  sourceFile: FileInfo
  targetFile: FileInfo
  strategy: ConflictStrategy
}
```

## 9. 示例流程

**场景**：用户选择源文件 `readme.txt`，目标目录 `/home/backup`，目标中已存在 `readme.txt`。

1. 前置校验通过（非文件夹，无需自包含检查）
2. 冲突检测：`/home/backup/readme.txt` 已存在
3. 弹出冲突对话框，用户选择“保留两者”
4. 生成新名称 `readme_20260510_143022.txt`
5. 调用复制 API：`copy('/home/docs/readme.txt', '/home/backup/readme_20260510_143022.txt')`
6. 成功 → 显示“复制成功” Toast，刷新目录
