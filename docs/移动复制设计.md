# 文件浏览器移动/复制操作设计文档（SFTP / WebDAV）

> **适用范围**：Rivet 项目的文件浏览器模块  
> **目标**：实现稳定、可预测、用户友好的移动（Move）和复制（Copy）功能

---

## 1. 概述

本设计文档基于 Rivet 项目的实际代码实现，定义了从源路径列表到目标目录的移动和复制操作的完整流程。

**分层架构**：

- **UI层**：`useFileOperations` 钩子处理用户交互、冲突检测、策略选择
- **协议层**：`FileProtocol` 接口定义协议操作，由 SFTP/WebDAV 实现

**核心文件**：

- `src/renderer/features/file-explorer/hooks/useFileOperations.ts` - 操作逻辑
- `src/renderer/features/file-explorer/components/ConflictDialog.tsx` - 冲突对话框
- `src/main/services/protocol/base.ts` - 协议接口定义
- `src/shared/utils/index.ts` - 工具函数

## 2. 术语定义

| 术语                      | 含义                                                       |
| ------------------------- | ---------------------------------------------------------- |
| **源路径（Source）**      | 单个文件或文件夹的远程绝对路径（`FileInfo.absolutePath`）  |
| **源列表（Sources）**     | 多个 `FileInfo` 对象组成的数组                             |
| **目标目录（TargetDir）** | 用户选中的目标文件夹（`FileInfo` 对象）                    |
| **操作类型**              | `move` 或 `copy`（来自 `FileOperation` 常量）              |
| **路径规范化**            | 使用 `normalizePath()` 转换为绝对路径，统一使用 `/` 分隔符 |
| **自包含限制**            | 禁止目标目录等于源文件夹自身或为源的后代路径               |

## 4. 同名冲突处理

### 4.1 冲突检测流程

```typescript
// 获取目标目录文件列表
const targetFiles = await window.electronAPI.protocol.list(sessionId, targetDir.absolutePath)
const existingFiles = new Map(targetFiles.map(f => [f.name, f]))

// 检测冲突
const foundConflicts: ConflictItem[] = []
for (const file of pendingFiles) {
  const existingFile = existingFiles.get(file.name)
  if (existingFile) {
    foundConflicts.push({
      sourceFile: file,
      targetFile: existingFile,
      targetExists: true,
    })
  }
}
```

### 4.2 冲突策略（用户可选项）

| 策略名称                 | 行为                                     | 适用场景                     |
| ------------------------ | ---------------------------------------- | ---------------------------- |
| **跳过（skip）**         | 不对该源项目执行任何操作，继续处理下一个 | 保留目标现有内容             |
| **保留两者（keepBoth）** | 自动为源项目生成新名称                   | 同时保留两份（默认策略）     |
| **覆盖（overwrite）**    | 用源项目替换目标中的同名项目             | 用户明确知道要替换（仅复制） |

> **注意**：移动操作不支持覆盖策略，仅支持 `skip` 和 `keepBoth`

### 4.3 保留两者的重命名算法

```typescript
export const generateUniqueName = (basename: string): string => {
  const extIndex = basename.lastIndexOf('.')
  const name = extIndex > 0 ? basename.substring(0, extIndex) : basename
  const ext = extIndex > 0 ? basename.substring(extIndex) : ''

  const now = new Date()
  const timestamp = `${now.getFullYear()}${String(now.getMonth() + 1).padStart(2, '0')}${String(now.getDate()).padStart(2, '0')}_${String(now.getHours()).padStart(2, '0')}${String(now.getMinutes()).padStart(2, '0')}${String(now.getSeconds()).padStart(2, '0')}_${String(now.getMilliseconds()).padStart(3, '0')}`

  return `${name}_${timestamp}${ext}`
}
```

**命名格式**：`name_YYYYMMDD_HHMMSS_mmm.ext`

### 4.4 特殊冲突：类型不匹配

```typescript
const canOverwrite = (conflict: ConflictItem): boolean => {
  const sourceType = conflict.sourceFile.type
  const targetType = conflict.targetFile?.type

  if (!targetType) return true
  if (sourceType === targetType) return true
  return false
}
```

- 类型不匹配时（文件 vs 文件夹），禁用"覆盖"选项
- 显示提示：无法将文件覆盖到同名文件夹（或反之）

### 4.5 批量冲突 UI

冲突对话框支持：

- 逐项选择处理策略
- `应用到所有剩余冲突` 复选框
- 全局策略按钮：全部跳过、全部保留两者（复制操作还支持全部覆盖）

## 5. 操作执行流程

### 5.1 总流程图

```
开始
  │
  ▼
用户选择文件 → 点击复制/移动
  │
  ▼
打开目标文件夹对话框
  │
  ▼
用户选择目标文件夹
  │
  ▼
自包含检查 ──失败→ 提示错误，结束
  │ 成功
  ▼
获取目标目录文件列表（protocol.list）
  │
  ▼
冲突检测
  │
  ├─ 有冲突 ─→ 弹出冲突对话框 → 用户选择策略
  │                    │
  └─ 无冲突 ───────────┘
                       │
                       ▼
              执行操作（循环处理每个源）
                       │
                       ├─ 根据策略构造目标路径
                       ├─ 调用协议 API（MOVE/COPY）
                       └─ 任何错误 → 停止并报告
                       │
                       ▼
                    刷新目录，结束
```

### 5.2 核心执行逻辑

```typescript
const executeOperation = async (files, targetDir, resolutionsMap, existingNames) => {
  const itemsToProcess = []

  for (const file of files) {
    const defaultTargetPath = getTargetPath(file.name, targetDir.absolutePath)
    const resolution = resolutionsMap.get(file.absolutePath)

    let targetPath = defaultTargetPath
    let shouldProcess = true

    if (resolution) {
      if (resolution.strategy === 'skip') {
        shouldProcess = false
      } else if (resolution.strategy === 'keepBoth') {
        const uniqueName = generateUniqueName(file.name)
        targetPath = getTargetPath(uniqueName, targetDir.absolutePath)
      }
    } else if (existingNames?.has(file.name)) {
      const uniqueName = generateUniqueName(file.name)
      targetPath = getTargetPath(uniqueName, targetDir.absolutePath)
    }

    if (!shouldProcess) continue
    itemsToProcess.push({ file, targetPath })
  }

  // 执行操作
  for (const { file, targetPath } of itemsToProcess) {
    if (op === FileOperation.COPY) {
      await window.electronAPI.protocol.copy(sessionId, file, targetPath)
    } else {
      await window.electronAPI.protocol.move(sessionId, file, targetPath)
    }
  }
}
```

## 7. 核心类型定义

```typescript
interface FileInfo {
  name: string
  type: 'file' | 'directory'
  size: number
  modifyTime: number
  absolutePath: string
}

type ConflictStrategy = 'overwrite' | 'skip' | 'keepBoth'

interface ConflictItem {
  sourceFile: FileInfo
  targetFile: FileInfo | null
  targetExists: boolean
}

interface ConflictResolution {
  sourceFile: FileInfo
  targetFile: FileInfo
  strategy: ConflictStrategy
}
```

## 9. 示例流程

**场景**：用户选择源文件 `readme.txt`，目标目录 `/home/backup`，目标中已存在 `readme.txt`。

1. 用户点击"复制"按钮 → 设置 `pendingOperation = 'copy'`，`pendingFiles = [readme.txt]`
2. 打开目标文件夹对话框，用户选择 `/home/backup`
3. 自包含检查通过（非文件夹）
4. 获取目标目录文件列表 → 发现冲突
5. 弹出冲突对话框，用户选择"保留两者"
6. 生成新名称 `readme_20260515_143022_123.txt`
7. 调用复制 API：`copy(sessionId, readme.txt, /home/backup/readme_20260515_143022_123.txt)`
8. 成功 → 显示"复制成功" Toast，刷新目录

## 11. 代码优化说明

### 11.1 性能优化

- 使用 `Map` 存储目标目录文件，O(1) 查找
- 缓存目标目录文件列表，避免重复请求

### 11.2 错误处理

- 使用 `fireAndForget` 处理异步操作，确保错误被捕获
- 操作失败时显示详细错误信息
