# 文件浏览器移动/复制操作设计文档（SFTP / WebDAV）

> **适用范围**：Rivet 项目的文件浏览器模块
> **目标**：实现稳定、可预测、用户友好的移动（Move）和复制（Copy）功能

---

## 1. 概述

本设计文档基于 Rivet 项目的实际代码实现，定义了从源路径列表到目标目录的移动和复制操作的完整流程。

**分层架构**：

- **UI层**：`useFileCopyMove` 和 `useFileOperations` 钩子处理用户交互、冲突检测、策略选择
- **协议层**：`FileProtocol` 接口定义协议操作，由 SFTP/WebDAV 实现

**核心文件**：

| 文件                                                                                       | 说明                                                     |
| ------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| [useFileOperations.ts](../src/renderer/features/file-explorer/hooks/useFileOperations.ts)  | 完整文件操作钩子（delete/rename/createFolder/copy/move） |
| [useFileCopyMove.ts](../src/renderer/features/file-explorer/hooks/useFileCopyMove.ts)      | 复制/移动专用钩子                                        |
| [ConflictDialog.tsx](../src/renderer/features/file-explorer/components/ConflictDialog.tsx) | 冲突对话框组件                                           |
| [abstract-protocol.ts](../src/main/services/protocol/abstract-protocol.ts)                 | 抽象协议接口                                             |
| [utils/index.ts](../src/shared/utils/index.ts)                                             | 工具函数（isSubPath, generateUniqueName）                |

## 2. 术语定义

| 术语                      | 含义                                                       |
| ------------------------- | ---------------------------------------------------------- |
| **源路径（Source）**      | 单个文件或文件夹的远程绝对路径（`FileInfo.absolutePath`）  |
| **源列表（Sources）**     | 多个 `FileInfo` 对象组成的数组                             |
| **目标目录（TargetDir）** | 用户选中的目标文件夹（`FileInfo` 对象）                    |
| **操作类型**              | `move` 或 `copy`（来自 `FileOperation` 常量）              |
| **路径规范化**            | 使用 `normalizePath()` 转换为绝对路径，统一使用 `/` 分隔符 |
| **自包含限制**            | 禁止目标目录等于源文件夹自身或为源的后代路径               |

## 3. 前置限制规则（客户端校验）

所有限制在**发起任何网络请求前**执行校验。

### 3.1 自包含检查

使用 `isSubPath()` 工具函数判断目标是否为源的子路径。

**规则说明**：

- 仅对文件夹类型进行检查
- 使用 [utils/index.ts](../src/shared/utils/index.ts) 中的 `isSubPath()` 函数
- 错误提示："无法将文件夹移动/复制到自身或其子文件夹"

## 4. 同名冲突处理

### 4.1 冲突检测流程

```
获取目标目录文件列表 → 构建名称 Map → 遍历源文件匹配 → 收集冲突项
```

详细实现见 [useFileOperations.ts#L236-246](../src/renderer/features/file-explorer/hooks/useFileOperations.ts#L236-246)

### 4.2 冲突策略（用户可选项）

| 策略名称                 | 行为                                     | 适用场景                     |
| ------------------------ | ---------------------------------------- | ---------------------------- |
| **跳过（skip）**         | 不对该源项目执行任何操作，继续处理下一个 | 保留目标现有内容             |
| **保留两者（keepBoth）** | 自动为源项目生成新名称                   | 同时保留两份（默认策略）     |
| **覆盖（overwrite）**    | 用源项目替换目标中的同名项目             | 用户明确知道要替换（仅复制） |

> **注意**：移动操作不支持覆盖策略，仅支持 `skip` 和 `keepBoth`

### 4.3 保留两者的重命名算法

使用 `generateUniqueName()` 生成唯一名称，格式为：`name_YYYYMMDD_HHMMSS_mmm.ext`

详细实现见 [utils/index.ts](../src/shared/utils/index.ts)

### 4.4 特殊冲突：类型不匹配

类型不匹配时（文件 vs 文件夹），禁用"覆盖"选项，显示提示：无法将文件覆盖到同名文件夹（或反之）

### 4.5 批量冲突 UI

冲突对话框支持：

- 逐项选择处理策略
- `应用到所有剩余冲突` 复选框
- 全局策略按钮：全部跳过、全部保留两者（复制操作还支持全部覆盖）

## 5. 操作执行流程

### 5.1 总流程图

```
开始
  │
  ▼
用户选择文件 → 点击复制/移动
  │
  ▼
打开目标文件夹对话框
  │
  ▼
用户选择目标文件夹
  │
  ▼
自包含检查 ──失败→ 提示错误，结束
  │ 成功
  ▼
获取目标目录文件列表（protocol.list）
  │
  ▼
冲突检测
  │
  ├─ 有冲突 ─→ 弹出冲突对话框 → 用户选择策略
  │                    │
  └─ 无冲突 ───────────┘
                       │
                       ▼
              执行操作（循环处理每个源）
                       │
                       ├─ 根据策略构造目标路径
                       ├─ 调用协议 API（MOVE/COPY）
                       └─ 任何错误 → 停止并报告
                       │
                       ▼
                    刷新目录，结束
```

### 5.2 核心执行逻辑

`executeOperation()` 方法负责根据冲突策略处理每个文件：

1. 遍历源文件列表
2. 根据策略决定目标路径（skip/keepBoth/overwrite）
3. 调用协议 API 执行操作
4. 处理错误并刷新目录

详细实现见 [useFileOperations.ts#L131-201](../src/renderer/features/file-explorer/hooks/useFileOperations.ts#L131-201)

### 5.3 协议层接口

```typescript
interface FileProtocol {
  copy(sessionId: string, file: FileInfo, targetPath: string): Promise<void>
  move(sessionId: string, file: FileInfo, targetPath: string): Promise<void>
}
```

## 6. 状态管理

### 6.1 钩子状态

| 状态               | 类型                                 | 说明                 |
| ------------------ | ------------------------------------ | -------------------- |
| `pendingOperation` | `'copy' \| 'move' \| null`           | 当前待执行的操作类型 |
| `pendingFiles`     | `FileInfo[]`                         | 待处理的源文件列表   |
| `pendingTargetDir` | `FileInfo \| null`                   | 用户选择的目标目录   |
| `conflicts`        | `ConflictItem[]`                     | 检测到的冲突列表     |
| `targetFilesCache` | `Map<string, 'file' \| 'directory'>` | 目标目录文件缓存     |

### 6.2 操作入口

```typescript
const handleCopy = (files: FileInfo[]) => {
  setPendingFiles(files)
  setPendingOperation(FileOperation.COPY)
  setTargetFolderDialogOpen(true)
}

const handleMove = (files: FileInfo[]) => {
  setPendingFiles(files)
  setPendingOperation(FileOperation.MOVE)
  setTargetFolderDialogOpen(true)
}
```

## 8. 错误处理与用户反馈

### 8.1 错误分类与反馈模板

| 错误类型   | 来源         | 用户提示                                  |
| ---------- | ------------ | ----------------------------------------- |
| 自包含违规 | 前置校验     | “无法将文件夹移动/复制到自身或其子文件夹” |
| 复制失败   | API 返回错误 | “复制失败：{错误信息}”                    |
| 移动失败   | API 返回错误 | “移动失败：{错误信息}”                    |

### 8.2 操作反馈

- 使用 Toast 提示操作成功/失败
- 成功后自动刷新当前目录

## 9. 示例流程

**场景**：用户选择源文件 `readme.txt`，目标目录 `/home/backup`，目标中已存在 `readme.txt`。

1. 用户点击"复制"按钮 → 设置状态
2. 打开目标文件夹对话框，用户选择 `/home/backup`
3. 自包含检查通过（非文件夹）
4. 获取目标目录文件列表 → 发现冲突
5. 弹出冲突对话框，用户选择"保留两者"
6. 生成新名称 `readme_20260515_143022_123.txt`
7. 调用复制 API
8. 成功 → 显示"复制成功" Toast，刷新目录

## 10. 协议 API 实现参考

| 操作         | SFTP 实现                 | WebDAV 实现                |
| ------------ | ------------------------- | -------------------------- |
| 复制文件     | 客户端实现（读取 → 写入） | `copyFile`（服务器端复制） |

## 11. 代码优化说明

### 11.1 性能优化

- 使用 `Map` 存储目标目录文件，O(1) 查找
- 缓存目标目录文件列表，避免重复请求

### 11.2 错误处理

- 使用 `isProtocolResponseErr()` 统一判断错误响应
- 操作失败时显示详细错误信息
