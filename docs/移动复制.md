# 文件浏览器移动/复制操作设计文档（SFTP / WebDAV）

> **版本**：1.0  
> **适用范围**：基于 SFTP 或 WebDAV 协议的文件浏览器  
> **目标**：实现稳定、可预测、用户友好的移动/复制功能，处理源为文件/文件夹/混合场景

---

## 1. 概述

本设计定义了从源路径 A（可以是文件、文件夹或它们的混合列表）到目标目录 B 的移动（Move）和复制（Copy）操作的逻辑约束、冲突处理策略和执行流程。

由于采用 SFTP 或 WebDAV 协议，操作具有远程、延迟高、状态不可完全信任等特性。本设计聚焦于**客户端必须执行的逻辑校验**和**用户交互策略**，将底层权限、空间、网络等错误交由协议 API 返回后统一处理。

---

## 2. 术语定义

| 术语                      | 含义                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| **源路径（Source）**      | 单个文件或文件夹的远程绝对路径                                    |
| **源列表（Sources）**     | 多个源路径组成的数组                                              |
| **目标目录（TargetDir）** | 用户选中的目标文件夹的绝对路径                                    |
| **操作类型**              | `move` 或 `copy`                                                  |
| **路径规范化**            | 转换为绝对路径，去除尾部斜杠，统一使用 `/` 分隔符，不跟随符号链接 |
| **自包含限制**            | 若源是文件夹，禁止目标目录等于源自身或为源的后代路径              |

---

## 3. 前置限制规则（客户端校验）

所有限制在**发起任何网络请求前**执行校验。校验失败则阻止操作并提示用户。

### 3.1 通用规则（适用于移动 & 复制）

| 规则                     | 校验逻辑                                | 错误提示                       |
| ------------------------ | --------------------------------------- | ------------------------------ |
| **TargetDir 必须存在**   | 通过 `stat(TargetDir)` 确认存在且为目录 | “目标文件夹不存在，请重新选择” |
| **TargetDir 不能为文件** | 同上                                    | “目标路径必须是一个文件夹”     |
| **路径规范化**           | 所有路径比较前均执行规范化              | （内部处理）                   |

### 3.2 自包含限制（仅针对文件夹源）

对于 sources 中的**每一个文件夹**，检查：

```
规范化(TargetDir) == 规范化(SourceFolder)
或
规范化(TargetDir) 以 规范化(SourceFolder) + "/" 开头
```

若满足任一条件，则**禁止整个操作**（而非跳过该源）。

> **为什么整个操作禁止？**  
> 避免出现部分成功、部分失败的不一致状态。用户应当自行调整目标选择或拆分操作。

- **错误提示**：  
  `“无法将文件夹“{源路径}”移动/复制到自身或其子文件夹中。请更换目标目录。”`

### 3.3 复制 vs 移动 的规则差异

| 规则                        | 复制                                   | 移动        |
| --------------------------- | -------------------------------------- | ----------- |
| 自包含限制                  | ✅ 需要                                | ✅ 需要     |
| 目标存在性                  | ✅ 必须存在                            | ✅ 必须存在 |
| 允许跨协议（SFTP → WebDAV） | ❌ 不允许（由 API 报错，无需前置检查） | ❌ 不允许   |

> 跨协议操作（如 SFTP 复制到 WebDAV）理论上可由客户端实现（读取后写入），但本设计不予支持，因为会导致性能差、原子性无保证。建议在 UI 层面禁止跨协议选择目标。

## 4. 同名冲突处理

当某个源项目的**基名**（basename）在目标目录中已经存在时，触发冲突处理。

### 4.1 冲突检测

检测文件名（区分大小写，根据协议调整，见 6.1 节）。  
对于每个源项目，独立判断是否存在 `TargetDir/basename`。

### 4.2 冲突策略（用户可选项）

| 策略名称       | 行为                                                               | 适用场景           |
| -------------- | ------------------------------------------------------------------ | ------------------ |
| **覆盖**       | 用源项目替换目标中的同名项目（对于文件夹，递归合并并覆盖冲突子项） | 用户明确知道要替换 |
| **跳过**       | 不对该源项目执行任何操作，继续处理下一个                           | 保留目标现有内容   |
| **保留两者**   | 自动为目标中已存在的项目重命名（对源项目原名不变）                 | 同时保留两份       |
| **手动重命名** | 提示用户输入一个新名称，用于源项目在目标中的名字                   | 精确控制           |

### 4.3 保留两者的重命名算法

为**目标中已存在的项目**生成新名称（避免多次 stat 请求）：

```
原始名：name.ext
新名称：name_YYYYMMDD_HHMMSS.ext
```

- 若新名称仍然存在（极小概率），则递归添加数字后缀 `_1`, `_2`... 最多尝试 10 次，若仍冲突则回退到“手动重命名”。
- 对于文件夹，同样规则（无扩展名部分追加时间戳）。

> 时间戳使用客户端本地时间，格式为 `YYYYMMDD_HHMMSS`。  
> **为什么不用 UUID？** 可读性差，不利于用户辨认。

### 4.4 特殊冲突：类型不匹配

如果源是文件，目标是同名文件夹（或相反），**覆盖策略无效**（底层 API 会失败）。

- 在冲突对话框中高亮显示此类冲突，并禁止选择“覆盖”，仅允许“跳过”、“保留两者”、“手动重命名”。
- 用户若尝试选择覆盖，提示“无法将文件覆盖到同名文件夹上”或反之。

### 4.5 批量冲突 UI 建议

弹窗展示冲突列表，每行包含：

- 源项目图标 + 名称
- 目标项目图标 + 名称
- 当前选择的策略（下拉或按钮组）

提供选项：

- `应用到所有剩余冲突` 复选框
- 全局按钮：`全部覆盖`、`全部跳过`、`全部保留两者`

## 5. 操作执行流程

### 5.1 总流程图

```
开始
  │
  ▼
前置校验（存在性、自包含）──失败→ 提示错误，结束
  │ 成功
  ▼
冲突检测
  │
  ├─ 无冲突 ──────────┐
  │                    │
  └─ 有冲突 ─→ 弹出冲突对话框 ─→ 用户选择策略
                              │
                              ▼
                      合并/重命名准备
                              │
                              ▼
                    执行操作（循环处理每个源）
                              │
                              ├─ 调用协议 API（MOVE/COPY）
                              │
                              └─ 任何错误 → 停止并报告，不回滚
                              │
                              ▼
                           结束
```

### 5.2 执行顺序

1. **排序（可选）**：对于移动操作，建议先移动文件，再移动文件夹，避免因为移动父文件夹导致子路径失效。但实际由于自包含限制已禁止这种情况，可以不排序。
2. **逐项处理**：对于每个源项目，根据冲突策略构造目标路径，调用协议 API。
3. **错误处理**：一旦某个项目失败，**立即停止整个操作**，向用户报告已完成的列表和失败的项，不进行自动回滚（用户可手动还原）。原因：远程操作回滚成本太高。

### 5.3 移动操作的特别说明

- 优先使用协议原生的 **MOVE** 命令（SFTP：`rename`；WebDAV：`MOVE` 方法）。这保证了在同一文件系统内是原子操作。
- 如果 MOVE 返回 `EXDEV`（跨设备）或类似错误，**不要**自动回退到“复制+删除”。因为：
  - 跨文件系统移动几乎保证失败（用户错误选择目标）
  - 自动回退会导致部分删除风险，且违背用户预期
  - 建议：直接报错提示“无法移动跨文件系统，请改用复制后手动删除源”
- 如果用户坚持要跨文件系统，可以在 UI 上提供“强制移动（复制+删除）”的高级选项，但需明确警告。

### 5.4 复制操作

- WebDAV：使用 `COPY` 方法（服务器端复制，高效）。
- SFTP：客户端实现复制（读取 → 写入），需支持进度回调、断点续传（可选）。不允许自包含限制已在前置中处理，不会产生无限递归。

## 6. 协议适配注意事项

### 6.1 路径大小写敏感性

- **默认假设**：服务器区分大小写（Unix-like）。所有比较（存在性、冲突检测、自包含）**区分大小写**。
- **例外**：如果从服务器信息中能明确得知大小写不敏感（如 Windows FTP/WebDAV），则改为不区分大小写比较。
- 实现方式：提供一个可配置的 `pathComparer` 函数，默认使用 `String.prototype.localeCompare(undefined, { sensitivity: 'case' })`。

### 6.2 路径规范化函数

```javascript
function normalizePath(path) {
  // 1. 确保以 / 开头（如果路径是相对的，需先转为绝对）
  // 2. 解析 . 和 ..
  // 3. 去除尾部斜杠（除非是根目录）
  // 4. 统一 / 分隔符（SFTP/WebDAV 均使用 /）
  // 5. 不跟随符号链接
  return resolvedPath
}
```

### 6.3 存在性与类型检查

- 使用协议提供的 `stat` 或 `propfind`（WebDAV）获取元数据。
- 为减少网络往返，建议在冲突检测阶段一次性获取目标目录的**文件列表**（`list`），然后本地内存中判断同名冲突。这样只需一次 `list` + 每个源一次 `stat`（如果需要区分文件/文件夹）。

优化策略：

```
1. list(TargetDir) → Map<basename, type>
2. 对每个源，检查 map 中是否有同名项
   - 有 → 触发冲突处理
   - 无 → 直接执行
3. 自包含检查需要源文件夹的 stat，无法避免
```

### 6.4 符号链接的处理

- 客户端**不跟随符号链接**进行路径比较。即：比较路径字符串本身，而非链接指向的真实路径。
- 当源是符号链接时：
  - 移动/复制操作作用于链接本身（作为文件或文件夹链接），而不是目标。
  - 冲突检测时，如果目标目录中已有同名符号链接，按普通文件/文件夹冲突处理。
  - 自包含限制：将链接视为普通文件夹（如果 `stat` 类型为 symlink 且指向目录），但检查时仍然基于它的路径字符串，不展开。这可能导致“看起来是子路径但实际不是”的允许误判？权衡下，字符串比较是最安全和可预测的。

## 7. 代码接口定义（供 AI IDE 实现）

### 7.1 核心函数签名（TypeScript 风格）

```typescript
interface FileItem {
  path: string // 绝对路径
  type: 'file' | 'directory' | 'symlink'
  size?: number
}

type ConflictStrategy = 'overwrite' | 'skip' | 'keepBoth' | 'rename'

interface ConflictResolution {
  sourcePath: string
  targetPath: string // 最终决定的目标路径
  strategy: ConflictStrategy
  userNewName?: string // 仅用于 rename
}

interface OperationOptions {
  operation: 'move' | 'copy'
  sources: string[]
  targetDir: string
  defaultConflictStrategy?: ConflictStrategy
  onConflict?: (conflicts: ConflictItem[]) => Promise<ConflictResolution[]>
  onProgress?: (current: number, total: number, path: string) => void
}

async function executeFileOperation(options: OperationOptions): Promise<{
  success: boolean
  completed: string[] // 成功的目标路径
  errors: Array<{ source: string; error: string }>
}>
```

### 7.2 辅助函数

```typescript
// 路径规范化
function normalize(p: string): string

// 判断 b 是否是 a 的子路径（严格）
function isSubPath(a: string, b: string): boolean

// 获取文件/文件夹类型（缓存友好）
async function getType(path: string): Promise<'file' | 'directory' | 'symlink' | null>

// 生成唯一名称用于 keepBoth
function generateUniqueName(basename: string, existingNames: Set<string>): string
```

## 8. 错误处理与用户反馈

### 8.1 错误分类与反馈模板

| 错误类型              | 来源                   | 用户提示                                                                       |
| --------------------- | ---------------------- | ------------------------------------------------------------------------------ |
| 目标目录不存在        | 前置校验               | “目标文件夹“{path}”不存在。是否创建？”（提供“创建”按钮，若用户同意则自动创建） |
| 自包含违规            | 前置校验               | “无法将“{src}”移动到/复制到自身或其子文件夹“{target}””                         |
| 目标不是目录          | 前置校验               | ““{target}”不是一个文件夹”                                                     |
| 移动跨设备            | API 返回 ENXIO / EXDEV | “无法跨文件系统移动。请改用复制，然后手动删除源文件。”                         |
| 复制/移动时文件被锁定 | API 返回 EACCES        | “文件“{path}”正被其他程序使用，无法操作”                                       |
| 磁盘空间不足          | API 返回 ENOSPC        | “目标服务器剩余空间不足”                                                       |
| 网络超时              | 协议层                 | “操作超时，请检查网络后重试”                                                   |
| 服务器内部错误        | API 返回 5xx           | “服务器错误：{详细错误码}”                                                     |

### 8.2 重试策略

- 不自动重试。对于网络超时等瞬时错误，可在 UI 上提供“重试”按钮，让用户手动发起。

### 8.3 操作日志

建议在界面底部显示简要操作日志（成功/失败/跳过），每条记录包含时间戳和文件名。

## 9. 示例流程（以复制文件夹为例）

**场景**：用户选择源文件夹 `/home/docs`，目标目录 `/home/docs/archive`，执行复制。

1. **校验**
   - 检查 `/home/docs/archive` 存在且是目录 → ✅
   - 自包含检查：目标 `/home/docs/archive` 是源 `/home/docs` 的子路径 → ❌ 禁止，提示错误。

**场景**：源文件 `readme.txt`，目标目录 `/home/backup`，目标中已存在 `readme.txt`。

1. 前置校验通过。
2. 冲突检测：`/home/backup/readme.txt` 已存在，类型为文件。
3. 弹出对话框，用户选择“保留两者”。
4. 客户端生成新名称 `readme_20260205_143022.txt`。
5. 调用复制 API：`copy('/home/docs/readme.txt', '/home/backup/readme_20260205_143022.txt')`。
6. 成功 → 显示“已复制 1 个文件”。

## 10. 附录：协议 API 映射参考

| 操作            | SFTP 方法          | WebDAV 方法                            |
| --------------- | ------------------ | -------------------------------------- |
| 检查存在性/类型 | `stat`             | `PROPFIND` (depth:0)                   |
| 列出目录内容    | `readdir`          | `PROPFIND` (depth:1)                   |
| 复制文件        | 客户端读写 + 创建  | `COPY` (目标覆盖取决于 `Overwrite` 头) |
| 移动/重命名     | `rename`           | `MOVE`                                 |
| 创建目录        | `mkdir`            | `MKCOL`                                |
| 删除            | `remove` / `rmdir` | `DELETE`                               |

> 对于支持服务器端复制的 SFTP 扩展（如 `copy-file` 扩展），可优先使用，提高性能。
