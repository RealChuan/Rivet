# 连接信息与活跃会话设计文档

## 概述

本文档详细描述了 Rivet 应用中连接配置信息（ConnectionConfig）与活跃会话（Session）的分离架构设计、数据结构和交互流程，完全基于当前项目的实际实现。

## 设计原则

1. **配置与状态分离**：连接配置和连接会话状态完全分离管理
2. **唯一标识清晰**：`id`（永久配置标识）与 `sessionId`（临时会话标识）严格区分
3. **职责明确**：配置管理、会话管理、文件操作各司其职
4. **安全存储**：密码通过 safeStorage 加密后作为 `encryptedPassword` 字段保存在配置中
5. **主机密钥验证**：仅 SFTP 协议需要，首次连接和密钥变更时进行验证；WebDAV 等其他协议不需要

## 核心概念

### 1. ConnectionConfig（连接配置）

**定义**：存储用户配置的连接信息，永久保存到本地存储（electron-store）。

**数据结构**：[connection.ts](../src/shared/types/connection.ts)

### 2. Session（活跃会话）

**定义**：表示当前正在进行的连接会话，包含连接状态和临时数据。

**数据结构**：[session.ts](../src/shared/types/session.ts)

### 3. SessionHandle（主进程会话句柄）

**定义**：主进程中维护的会话句柄，包含协议客户端实例和连接配置。

**数据结构**：[SessionManager.ts](../src/main/services/SessionManager.ts)

## 状态管理

### ConnectionStore（连接配置管理）

基于 Zustand 实现，管理所有保存的连接配置：

- **位置**：[connection.store.ts](../src/renderer/features/session/stores/connection.store.ts)
- **核心方法**：
  - `addConnection`: 添加新连接配置
  - `updateConnection`: 更新连接配置
  - `deleteConnection`: 删除连接配置（同步到主进程）
  - `loadSavedConnections`: 从主进程加载保存的配置

### SessionStore（会话状态管理）

基于 Zustand 实现，管理当前活跃会话：

- **位置**：[session.store.ts](../src/renderer/features/session/stores/session.store.ts)
- **核心方法**：
  - `connectSession`: 建立新会话
  - `reconnectSession`: 重新建立会话
  - `addSession`: 添加会话到状态
  - `removeSession`: 移除会话
  - `refreshCurrentDirectory`: 刷新当前目录

### HostKeyStore（主机密钥对话框管理）

基于 Zustand 实现，管理 SFTP 主机密钥验证对话框状态：

- **位置**：[host-key.store.ts](../src/renderer/features/host-key/stores/host-key.store.ts)

## 主要交互流程

### 1. 新建连接流程

```
用户点击"新建连接" → SessionSidebar.handleNewConnection()
    ↓
弹出连接对话框 ConnectionDialog，用户填写表单
    ↓
用户点击"保存"
    ↓
SessionSidebar.handleSaveConnection(config)
    ↓
生成 id（UUID）
    ↓
构建 fullConfig（包含加密密码）
    ↓
SessionStore.connectSession(fullConfig)
    ↓
handleConnectWithHostKey(config)
    ↓
electronAPI.protocol.connect(fullConfig)
    ↓
协议层返回 { sessionId, statusCode, detail }
    ├─ statusCode == OK → 创建 Session，刷新目录
    ├─ statusCode == FIRST_CONNECT（SFTP）→ 显示主机密钥确认对话框
    └─ statusCode == HOST_KEY_MISMATCH（SFTP）→ 显示密钥变更警告对话框
    ↓
用户确认主机密钥后（如需要）
    ↓
ConnectionStore.addConnection(fullConfig)
    ↓
ConnectionStore.saveConnections() → electron-store
    ↓
密码通过 safeStorage 加密后保存到配置（如果 savePassword 为 true）
```

### 2. 编辑连接流程

```
用户点击"编辑"按钮
    ↓
SessionSidebar.handleEdit(connection)
    ↓
如果当前已连接，先断开连接：
    ├─ 获取 sessionId
    ├─ electronAPI.protocol.disconnect(sessionId)
    └─ SessionStore.removeSession(sessionId)
    ↓
弹出连接编辑对话框，用户修改配置
    ↓
用户点击"保存"
    ↓
SessionSidebar.handleSaveConnection(config)
    ↓
使用原有 id
    ↓
构建 fullConfig（包含加密密码）
    ↓
SessionStore.connectSession(fullConfig)
    ↓
handleConnectWithHostKey(config)
    ↓
协议层返回连接结果
    ↓
用户确认主机密钥后（如需要）
    ↓
ConnectionStore.updateConnection(fullConfig)
    ↓
ConnectionStore.saveConnections() → electron-store
```

### 3. 侧边栏点击连接流程

```
用户点击侧边栏连接项
    ↓
SessionSidebar.handleReconnect(connection)
    ↓
检查是否有保存的密码：
    ├─ 有保存的密码 → 直接进入连接流程
    └─ 无保存的密码 → 弹出连接对话框让用户输入密码
        ↓
用户输入密码，点击确认
        ↓
SessionSidebar.handleReconnectSubmit(config)
    ↓
SessionStore.reconnectSession(id, { encryptedPassword, savePassword })
    ↓
SessionStore.connectSession(config)
    ↓
handleConnectWithHostKey(config)
    ↓
协议层返回 { sessionId, statusCode, detail }
    ├─ statusCode == OK → 创建/更新 Session，刷新目录
    ├─ statusCode == FIRST_CONNECT（SFTP）→ 显示主机密钥确认对话框
    └─ statusCode == HOST_KEY_MISMATCH（SFTP）→ 显示密钥变更警告对话框
```

### 4. SFTP 主机密钥验证流程

#### 首次连接（FIRST_CONNECT）

```
协议层返回 FIRST_CONNECT
    ↓
handleConnectWithHostKey() 调用 showHostKeyDialog()
    ↓
HostKeyStore.setHostKeyDialog({ type: 'first-connect', ... }) 显示信息提示对话框
    ↓
用户选择：
    ├─ 点击"信任并保存" → 调用 onConfirm()
    └─ 点击"断开连接" → 调用 onCancel()
```

**用户点击"信任并保存"：**

```
onConfirm() 被调用
    ↓
resolve(true)
    ↓
handleConnectWithHostKey() 继续执行
    ↓
electronAPI.hostKey.saveKnownHost({ id, hash })
    ↓
返回 { success: true, sessionId, retry: false }
    ↓
connectSession() 创建 Session，刷新目录
    ↓
ConnectionStore.addConnection(fullConfig)
    ↓
ConnectionStore.saveConnections()
```

**用户点击"断开连接"：**

```
onCancel() 被调用
    ↓
resolve(false)
    ↓
handleConnectWithHostKey() 执行清理：
    ├─ electronAPI.protocol.disconnect(sessionId)
    └─ electronAPI.hostKey.deleteKnownHost(id)
    ↓
返回 { success: false, sessionId: null, retry: false }
    ↓
connectSession() 返回 false
    ↓
handleSaveConnection() 抛出错误，不保存配置
```

#### 密钥变更（HOST_KEY_MISMATCH）

```
协议层返回 HOST_KEY_MISMATCH
    ↓
handleConnectWithHostKey() 调用 showHostKeyDialog()
    ↓
HostKeyStore.setHostKeyDialog({ type: 'mismatch', ... }) 显示危险警告对话框
    ↓
用户选择：
    ├─ 点击"信任" → 调用 onConfirm()
    └─ 点击"关闭" → 调用 onCancel()
```

**用户点击"信任"：**

```
onConfirm() 被调用
    ↓
resolve(true)
    ↓
handleConnectWithHostKey() 继续执行
    ↓
electronAPI.hostKey.saveKnownHost({ id, hash })
    ↓
返回 { success: false, sessionId: null, retry: true }
    ↓
connectSession() 检测到 retry: true，再次调用 handleConnectWithHostKey()
    ↓
重新连接成功后创建/更新 Session
```

**用户点击"关闭"：**

```
onCancel() 被调用
    ↓
resolve(false)
    ↓
handleConnectWithHostKey() 返回 { success: false, sessionId: null, retry: false }
    ↓
connectSession() 返回 false
    ↓
不保存配置，保持原有状态
```

### 5. 断开连接流程

```
用户点击"断开"按钮
    ↓
SessionSidebar.handleDisconnect(id)
    ↓
获取 id 对应的 Session
    ↓
electronAPI.protocol.disconnect(sessionId)
    ↓
SessionStore.removeSession(sessionId)
    ↓
ConnectionConfig 仍保留在 connections 数组中（可重新连接）
```

### 6. 删除连接流程

```
用户点击"删除"按钮
    ↓
SessionSidebar.handleDelete(id)
    ↓
弹出确认对话框
    ↓
用户确认删除
    ↓
SessionSidebar.handleConfirmDelete()
    ↓
如果已连接，先断开：
    ├─ electronAPI.protocol.disconnect(sessionId)
    └─ SessionStore.removeSession(sessionId)
    ↓
ConnectionStore.deleteConnection(id)
    ↓
从 connections 数组中移除配置
    ↓
electronAPI.config.storeSet('saved_connections', updatedConnections)
    ↓
electronAPI.config.deleteConnection(id)
```

## 数据持久化

### 保存的内容

| 数据类型         | 存储位置       | 是否加密 | 说明                                |
| ---------------- | -------------- | -------- | ----------------------------------- |
| ConnectionConfig | electron-store | 部分加密 | 密码字段通过 safeStorage 加密后存储 |
| 主机密钥         | electron-store | 否       |                                     |
| Session          | 内存（临时）   | -        |                                     |

### 启动加载流程

```
应用启动
    ↓
ConnectionStore.loadSavedConnections()
    ↓
electronAPI.config.getSavedConnections()
    ↓
读取 electron-store 中的 ConnectionConfig 列表
    ↓
填充到 connections 数组
    ↓
sessions 数组初始为空
    ↓
用户在侧边栏看到所有配置
    ↓
用户点击连接建立会话
```

## SFTP 主机密钥验证机制

### 验证时机

| 场景     | 触发条件                          | 对话框类型     |
| -------- | --------------------------------- | -------------- |
| 首次连接 | 连接的主机密钥不在 known-hosts 中 | 信息提示对话框 |
| 密钥变更 | 主机密钥与已保存的不匹配          | 危险警告对话框 |

### 状态码定义

- **ProtocolStatus.OK (2000)**：连接成功
- **ProtocolStatus.FIRST_CONNECT (2001)**：首次连接，需要确认主机密钥
- **SftpStatus.HOST_KEY_MISMATCH (3000)**：主机密钥不匹配，存在安全风险

### 关键实现函数

**showHostKeyDialog**（[session.store.ts](../src/renderer/features/session/stores/session.store.ts#L67-97)）：

- 显示主机密钥对话框
- 返回 Promise，用户确认时 resolve(true)，取消时 resolve(false)

**handleConnectWithHostKey**（[session.store.ts](../src/renderer/features/session/stores/session.store.ts#L99-162)）：

- 处理连接和主机密钥验证逻辑
- 根据协议返回的状态码决定下一步操作
- 返回 `{ success: boolean, sessionId: string | null, retry: boolean }`

**connectSession**（[session.store.ts](../src/renderer/features/session/stores/session.store.ts#L287-311)）：

- 建立会话的入口函数
- 循环处理 retry 逻辑，支持多次连接尝试

## 安全考虑

1. **密码安全**：密码通过 safeStorage 加密后作为 `encryptedPassword` 字段保存在配置文件中
2. **主机密钥验证**：仅 SFTP 连接时验证主机密钥，防止中间人攻击
3. **输入验证**：所有用户输入经过严格的类型检查和 sanitize 处理
4. **SSL 证书验证**：WebDAV HTTPS 连接默认验证 SSL 证书

## 总结

当前实现的连接信息与活跃会话架构具有以下特点：

✅ **配置与状态分离**：`ConnectionConfig` 持久保存，`Session` 动态管理  
✅ **安全存储**：密码通过 safeStorage 加密存储  
✅ **主机密钥验证**：SFTP 连接的安全保障  
✅ **重试机制**：支持自动重试处理密钥变更后的重新连接  
✅ **清晰的职责划分**：配置管理、会话管理、文件操作各司其职  
✅ **良好的扩展性**：支持多协议、多会话

这是一个清晰、安全且易于维护的架构设计。
