# 连接信息与活跃会话设计文档

## 概述

本文档详细描述了 Rivet 应用中连接配置信息（ConnectionConfig）与活跃会话（Session）的分离架构设计、数据结构和交互流程。

## 设计原则

1. **配置与状态分离**：连接配置和连接会话状态完全分离管理
2. **唯一标识清晰**：区分永久不变的配置标识和动态变化的会话标识
3. **职责明确**：配置管理、会话管理、文件操作各司其职
4. **灵活可扩展**：支持未连接的配置展示、多协议适配

## 核心概念

### 1. ConnectionConfig（连接配置）

**定义**：存储用户配置的连接信息，永久保存到本地存储。

**特点**：

- `connectionUuid` 是永久不变的唯一标识符
- 包含所有建立连接所需的参数
- 不受连接状态影响，连接断开后配置依然存在

**数据结构**：

```typescript
interface ConnectionConfig {
  connectionUuid: string // 永久唯一标识（UUID）
  name: string // 用户自定义连接名称
  protocol: 'sftp' | 'webdav' // 协议类型
  host: string // 服务器地址
  port: number // 端口号
  username: string // 用户名
  password?: string // 密码（可选）
  basePath?: string // 基础路径（可选）
  scheme?: 'http' | 'https' // WebDAV专用：协议方案（可选）
  rejectUnauthorized?: boolean // WebDAV专用：SSL证书验证（可选）
}
```

### 2. Session（活跃会话）

**定义**：表示当前正在进行的连接会话，包含连接状态和临时数据。

**特点**：

- `sessionId` 由协议层动态生成，每次连接都会变化
- `connectionUuid` 关联到对应的连接配置
- 包含连接状态、当前路径、文件列表等临时数据
- 连接断开后可清理或保留用于重连

**数据结构**：

```typescript
interface Session {
  sessionId: string // 临时会话标识（协议层生成）
  connectionUuid: string // 关联的配置ID
  currentPath: string // 当前目录路径
  files: FileInfo[] // 当前目录文件列表
  isConnected: boolean // 连接状态
  isLoading: boolean // 加载状态
  error: string | null // 错误信息
}
```

## 状态管理

### sessionStore（会话状态管理）

```typescript
interface SessionStore {
  connections: ConnectionConfig[] // 所有保存的连接配置
  sessions: Session[] // 当前活跃会话
  activeSessionId: string | null // 当前激活的会话ID

  // 连接配置操作
  addConnection: (config: Omit<ConnectionConfig, 'connectionUuid'>) => Promise<string>
  updateConnection: (
    connectionUuid: string,
    config: Omit<ConnectionConfig, 'connectionUuid'>
  ) => Promise<void>
  removeConnection: (connectionUuid: string) => void
  deleteConnection: (connectionUuid: string) => void

  // 会话操作
  setActiveSession: (sessionId: string) => void
  reconnectSession: (connectionUuid: string, password?: string) => Promise<void>
  loadSavedConnections: () => Promise<void>

  // 文件操作
  updateCurrentPath: (sessionId: string, path: string) => void
  setFiles: (sessionId: string, files: FileInfo[]) => void
  setLoading: (sessionId: string, loading: boolean) => void
  setError: (sessionId: string, error: string | null) => void
  refreshCurrentDirectory: (sessionId: string) => Promise<void>

  // 辅助查询
  getSessionByconnectionUuid: (connectionUuid: string) => Session | undefined
  getSessionById: (sessionId: string) => Session | undefined
}
```

## 主要交互流程

### 1. 新建连接流程

```
用户点击"新建连接"
    ↓
用户填写连接表单
    ↓
生成 connectionUuid
    ↓
调用 protocol.connect()
    ↓
协议层返回 sessionId
    ↓
创建 Session 对象（关联 connectionUuid）
    ↓
保存 ConnectionConfig 到本地存储
    ↓
添加到 connections 数组
    ↓
添加到 sessions 数组
    ↓
设置为 activeSessionId
    ↓
刷新目录列表
```

### 2. 重连流程

```
用户点击"重连"
    ↓
获取该 connectionUuid 对应的 ConnectionConfig
    ↓
调用 protocol.connect()
    ↓
协议层返回新的 sessionId
    ↓
移除旧的 Session（如果存在）
    ↓
创建新的 Session 对象
    ↓
添加到 sessions 数组
    ↓
设置为 activeSessionId
    ↓
刷新目录列表
```

### 3. 编辑配置流程

```
用户点击"编辑"
    ↓
获取该 connectionUuid 对应的 ConnectionConfig
    ↓
用户修改配置
    ↓
如果当前已连接，先 disconnect()
    ↓
更新 connections 数组中的配置
    ↓
保存到本地存储
    ↓
如果之前是连接状态，重新 connect()
    ↓
创建新的 Session
    ↓
刷新目录列表
```

### 4. 断开连接流程

```
用户点击"断开"
    ↓
调用 protocol.disconnect(sessionId)
    ↓
从 sessions 数组中移除
    ↓
如果是 activeSession，清空 activeSessionId
    ↓
（ConnectionConfig 仍在 connections 数组中）
```

### 5. 删除连接流程

```
用户点击"删除"
    ↓
如果已连接，先 disconnect()
    ↓
从本地存储中删除 ConnectionConfig
    ↓
从 connections 数组中移除
    ↓
从 sessions 数组中移除
    ↓
如果是 activeSession，清空 activeSessionId
```

## UI 组件映射

### SessionSidebar（左侧边栏）

- **数据来源**：`connections` 数组
- **展示内容**：所有保存的连接配置
- **状态展示**：
  - 已连接：绿色图标 + 协议图标
  - 未连接：橙色图标 + 连接图标
  - 加载中：旋转动画
- **操作**：连接、断开、编辑、删除、重连

### SessionItem（单个会话项）

```tsx
interface SessionItemProps {
  connection: ConnectionConfig // 连接配置
  session?: Session // 对应的会话（如果已连接）
  isActive: boolean
  onSelect: () => void
  onDisconnect: () => void
  onReconnect: () => void
  onDelete: () => void
  onEdit: () => void
}
```

### FileAreaContainer（文件区域容器）

- **数据来源**：`sessions` 数组
- **展示内容**：当前激活会话的文件列表
- **多个会话切换**：通过 `activeSessionId` 控制显示哪个会话

## 协议层接口

### protocol-handlers.ts

```typescript
// 建立连接
ipcMain.handle('protocol:connect', async (_event, config: ConnectionConfig) => {
  const sessionId = protocol.connect(config)
  return sessionId // 返回 sessionId，不是 connectionUuid
})

// 断开连接
ipcMain.handle('protocol:disconnect', async (_event, sessionId: string) => {
  protocol.disconnect(sessionId)
})

// 所有协议操作都使用 sessionId
ipcMain.handle('protocol:list', async (_event, sessionId: string, path: string) => {
  return protocol.list(sessionId, path)
})
```

### BaseProtocol（基础协议类）

```typescript
abstract class BaseProtocolImpl<T> {
  protected sessions: Map<string, SessionHandle<T>> = new Map()
  // key: sessionId（协议层生成）
}
```

## 数据持久化

### 保存的内容

- **ConnectionConfig**：全部保存到本地存储
- **Session**：不保存（会话是临时的）

### 启动加载

```
应用启动
    ↓
loadSavedConnections()
    ↓
读取本地存储的 ConnectionConfig
    ↓
填充到 connections 数组
    ↓
sessions 数组初始为空
    ↓
用户可以在 sidebar 看到所有配置
    ↓
用户可以点击连接建立会话
```

## 错误处理

### 连接失败

1. 显示错误消息给用户
2. 不创建 Session 对象
3. 保留 ConnectionConfig

### 连接断开

1. 更新 Session 的 isConnected = false
2. 清除错误信息或显示断开原因
3. 保留 Session 在数组中（可选，用于显示断开状态）

### 操作错误

1. 设置 Session.error = errorMessage
2. 可选：自动断开连接

## 性能考虑

### 查找效率

- 通过 `connectionUuid` 查找 Session：`O(n)`（正常情况下 n 很小）
- 通过 `sessionId` 查找 Session：`O(n)`
- 如果需要更高性能，可考虑建立索引 Map

### 内存管理

- 断开连接后可以清理 Session
- 保留最近使用的 Session 缓存（可选）

## 扩展点

### 多协议支持

通过 `ConnectionConfig.protocol` 字段区分，新增协议只需：

1. 在类型定义中添加新协议枚举
2. 实现对应的 Protocol 类
3. 在 ProtocolFactory 中注册

### 多标签页/多窗口

每个窗口/标签页可以有自己的 `activeSessionId`，但共享同一个 `connections` 配置列表。

### 会话快照

可选功能：保存 Session 的状态（当前路径等），下次连接时恢复。

## 类型安全

### 关键类型检查

```typescript
// ConnectionConfig 必须有 connectionUuid
type ValidConnectionConfig = ConnectionConfig & Required<Pick<ConnectionConfig, 'connectionUuid'>>

// Session 必须关联到 connectionUuid
type ValidSession = Session & Required<Pick<Session, 'connectionUuid'>>
```

### 类型守卫

```typescript
function isConnectionConfig(obj: any): obj is ConnectionConfig {
  return obj && typeof obj.connectionUuid === 'string'
}

function isSession(obj: any): obj is Session {
  return obj && typeof obj.sessionId === 'string' && typeof obj.connectionUuid === 'string'
}
```

## 总结

这个设计通过清晰的职责分离、明确的标识体系和灵活的数据结构，实现了：

✅ 配置永久保存，会话动态管理  
✅ 支持未连接配置的展示和管理  
✅ 连接断开不丢失配置信息  
✅ 每次连接有独立的 sessionId，便于协议层管理  
✅ 良好的扩展性，易于添加新功能

这是一个清晰、灵活且易于维护的架构设计。
