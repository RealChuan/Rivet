# 连接信息与活跃会话设计文档

## 概述

本文档详细描述了 Rivet 应用中连接配置信息（ConnectionConfig）与活跃会话（Session）的分离架构设计、数据结构和交互流程，完全基于当前项目的实际实现。

## 设计原则

1. **配置与状态分离**：连接配置和连接会话状态完全分离管理
2. **唯一标识清晰**：`connectionUuid`（永久配置标识）与 `sessionId`（临时会话标识）严格区分
3. **职责明确**：配置管理、会话管理、文件操作各司其职
4. **安全存储**：密码通过 keytar 安全存储，不保存到配置文件
5. **主机密钥验证**：仅 SFTP 协议需要，首次连接和密钥变更时进行验证；WebDAV 等其他协议不需要

## 核心概念

### 1. ConnectionConfig（连接配置）

**定义**：存储用户配置的连接信息，永久保存到本地存储（electron-store）。

**特点**：

- `connectionUuid` 是永久不变的唯一标识符（UUID）
- 包含所有建立连接所需的参数
- 密码通过 keytar 存储，不在配置中持久化
- 不受连接状态影响，连接断开后配置依然存在

**数据结构**（`shared/types/connection.ts`）：

```typescript
interface ConnectionConfig {
  connectionUuid: string // 永久唯一标识（UUID）
  name: string // 用户自定义连接名称
  protocol: ProtocolType // 协议类型（sftp | webdav）
  host: string // 服务器地址
  port: number // 端口号
  username: string // 用户名
  password?: string // 密码（仅运行时使用，不存储）
  savePassword?: boolean // 是否保存密码到 keytar
  basePath?: string // WebDAV 基础路径
  scheme?: 'http' | 'https' // WebDAV 协议方案
  rejectUnauthorized?: boolean // WebDAV SSL 证书验证
}

// 不含密码的版本，用于存储和传输
export type ConnectionConfigWithoutPassword = Omit<ConnectionConfig, 'password'>
```

### 2. Session（活跃会话）

**定义**：表示当前正在进行的连接会话，包含连接状态和临时数据。

**特点**：

- `sessionId` 由协议层动态生成，每次连接都会变化
- `connectionUuid` 关联到对应的连接配置
- 包含连接状态、当前路径、文件列表等临时数据
- 连接断开后可清理或保留用于重连

**数据结构**（`shared/types/session.ts`）：

```typescript
interface Session {
  sessionId: string // 协议层返回的会话 ID
  connectionUuid: string // 关联的配置 ID
  currentPath: string // 当前目录路径
  files: FileInfo[] // 当前目录文件列表
  isConnected: boolean // 是否已连接
  isLoading: boolean // 是否正在加载
  error: string | null // 错误信息
}
```

## 状态管理

### sessionStore（会话状态管理）

基于 Zustand 实现的状态管理（`renderer/features/session/stores/sessionStore.ts`）：

```typescript
interface SessionStore {
  // 状态
  connections: ConnectionConfigWithoutPassword[] // 所有保存的连接配置

    connectionUuid: string,

  removeConnection: (connectionUuid: string) => Promise<void> // 仅断开，保留配置

  setHostKeyDialog: (state: Partial<HostKeyDialogState>) => void
  closeHostKeyDialog: () => void

  // 辅助查询
  getSessionByconnectionUuid: (connectionUuid: string) => Session | undefined
  getSessionById: (sessionId: string) => Session | undefined
}
```

## 安全机制：主机密钥验证

SFTP 连接时的安全验证流程：

```typescript
// 状态码定义
const ProtocolStatus = {
  OK: 2000, // 连接成功
  FIRST_CONNECT: 2001, // 首次连接，需要确认主机密钥
}

const SftpStatus = {
  HOST_KEY_MISMATCH: 3000, // 主机密钥不匹配，存在安全风险
}
```

**验证流程**：

1. **首次连接（FIRST_CONNECT）**：显示确认对话框，用户确认后保存密钥
2. **密钥变更（HOST_KEY_MISMATCH）**：显示警告对话框，提示用户可能存在中间人攻击

## 主要交互流程

### 1. 新建连接流程

```
用户点击"新建连接"
    ↓
用户填写连接表单
    ↓
生成 connectionUuid (uuidv4)
    ↓
调用 electronAPI.protocol.connect(config)
    ↓
协议层返回 { sessionId, statusCode, detail }
    ↓
├─ statusCode == OK → 创建 Session，刷新目录
├─ statusCode == FIRST_CONNECT → 显示主机密钥确认对话框（SFTP）
└─ statusCode == HOST_KEY_MISMATCH → 显示密钥变更警告对话框（SFTP）
    ↓
保存 ConnectionConfig 到 electron-store
    ↓
保存密码到 keytar（如果 savePassword 为 true）
```

### 2. 重连流程

```
用户点击"重连"
    ↓
获取 connectionUuid 对应的 ConnectionConfig
    ↓
从 keytar 获取密码（如果已保存）
    ↓
调用 electronAPI.protocol.connect(config)
    ↓
协议层返回新的 sessionId
    ↓
移除旧的 Session（如果存在）
    ↓
创建新的 Session 对象
    ↓
刷新目录列表
```

### 3. 编辑配置流程

```
用户点击"编辑"
    ↓
获取 connectionUuid 对应的 ConnectionConfig
    ↓
用户修改配置
    ↓
如果当前已连接，先 disconnect()
    ↓
更新 connections 数组中的配置
    ↓
保存到本地存储
    ↓
如果之前是连接状态且有密码，重新 connect()
```

### 4. 断开连接流程（removeConnection）

```
用户点击"断开"
    ↓
调用 electronAPI.protocol.disconnect(sessionId)
    ↓
从 sessions 数组中移除
    ↓
如果是 activeSession，清空 activeSessionId
    ↓
(ConnectionConfig 仍在 connections 数组中，可重新连接)
```

### 5. 删除连接流程（deleteConnection）

```
用户点击"删除"
    ↓
如果已连接，先 disconnect()
    ↓
从 keytar 删除密码（如果存在）
    ↓
调用 electronAPI.common.deleteConnection(connectionUuid)
    ↓
从 connections 数组中移除
    ↓
从 sessions 数组中移除
    ↓
如果是 activeSession，清空 activeSessionId
```

## 数据持久化

### 保存的内容

| 数据类型         | 存储位置                 | 是否加密 |
| ---------------- | ------------------------ | -------- |
| ConnectionConfig | electron-store           | 否       |
| 密码             | keytar（系统凭据管理器） | 是       |
| 主机密钥         | electron-store           | 否       |
| Session          | 内存（临时）             | -        |

### 启动加载流程

```
应用启动
    ↓

    ↓
读取 electron-store 中的 ConnectionConfig 列表
    ↓
填充到 connections 数组
    ↓
sessions 数组初始为空
    ↓
用户在侧边栏看到所有配置
    ↓
用户点击连接建立会话
```

## 性能优化

### 请求防重入

使用 `requestCounters` 防止重复请求：

```typescript
refreshCurrentDirectory: async sessionId => {
  const currentCount = (get().requestCounters[sessionId] ?? 0) + 1
  set({ requestCounters: { ...state.requestCounters, [sessionId]: currentCount } })

  // 请求完成后检查计数器，防止过时的响应覆盖最新状态
  if (get().requestCounters[sessionId] !== currentCount) {
    return
  }
}
```

## 安全考虑

1. **密码安全**：密码通过 keytar 存储到系统凭据管理器，不在配置文件中明文保存
2. **主机密钥验证**：仅 SFTP 连接时验证主机密钥，防止中间人攻击；WebDAV 等其他协议不涉及此验证
3. **输入验证**：所有用户输入经过严格的类型检查和 sanitize 处理
4. **SSL 证书验证**：WebDAV HTTPS 连接默认验证 SSL 证书

## 错误处理

### 连接失败

1. 显示错误消息给用户
2. 不创建 Session 对象
3. 保留 ConnectionConfig

### 连接断开

1. 更新 Session 的 `isConnected = false`
2. 设置 `error` 字段
3. 保留 Session 在数组中（显示断开状态）

### 操作错误

1. 设置 `Session.error = errorMessage`
2. 断开连接

## 总结

当前实现的连接信息与活跃会话架构具有以下特点：

✅ **配置与状态分离**：`ConnectionConfig` 持久保存，`Session` 动态管理  
✅ **安全存储**：密码通过 keytar 安全存储  
✅ **主机密钥验证**：SFTP 连接的安全保障  
✅ **请求防重入**：避免重复操作导致的状态混乱  
✅ **清晰的职责划分**：配置管理、会话管理、文件操作各司其职  
✅ **良好的扩展性**：支持多协议、多会话

这是一个清晰、安全且易于维护的架构设计。
